## How data flows

- Each device keeps its data in `localStorage` (`wismir_v1` dashboard, `wismir_pos_v1` POS) and syncs to one Google Sheet through `Code.gs` (URL + PIN entered in each device's settings, never in the code).
- **Dashboard tabs** (`Keuangan`, `Stok`, `Tugas`, `Purchasing`, `Staff`, `Store`, `Production`, `Marketing`): the dashboard rewrites the whole tab on save. A version number (`dashVer`) rejects saves based on stale data; the dashboard then merges row by row (add/edit/delete by id) and retries. It reloads on focus and every 5 minutes.
- **Products and staff are managed only in the dashboard** (`Stok`, `Staff` tabs) and shared with the POS. The POS reads them on every pull. Products have `kategori` (POS cashier filter) and `aktif` (`Active`/`Inactive`, Inactive = hidden from the cashier). A product with POS history can only be set Inactive, never deleted. Store/warehouse stock is computed from POS moves; the dashboard only types **online** stock (`stokOnline`). `stokToko` is a dead legacy column kept so column order does not shift.
- **POS tabs** (`POS Stok`, `POS Kasir`, `POS Shift`, `POS Absen`): rows are upserted by id with a server timestamp `_upd`; tablets pull changes since their last sync every minute. `POS Produk` / `POS Karyawan` are archives from the old POS; the dashboard copies their rows into `Stok` / `Staff` once (same id).
- **Owner's rule for the POS:** stock moves sync immediately (offline queue, retried). Receipts, shift summary and attendance upload **only when the shift is closed**, so the cashier never waits for the network. Do not change this.
- The PIN lives in Apps Script **Script Properties**, set from the Sheet menu **WISMIR → Atur PIN**. Never write a real PIN into any file in this repo (it is public).
- Text cells are written with plain-text format so Sheets never turns `2026-11-04` into a date; numeric columns are listed in `NUM` in `Code.gs`. Dates in the apps use local `ymd()` helpers, never `toISOString()` (UTC shifts the day in Jakarta).

## Owner's decisions (do not undo)

- No cash-count field at shift close: the owner checks differences with staff directly.
- POS prices are typed per sale (bargaining in store) with "frequently used price" chips. No fixed price list in the POS.
- POS Owner menu has only **Laporan** and **Data**. Products/staff are not editable on the tablet.
- Attendance = who was ticked when the shift opened (no clock-in/out yet).
- The POS has **no sample data**. Products, staff and store locations come only from the dashboard; local items unknown to the dashboard are dropped on sync (except ones still queued for upload from an old tablet). Sample data for previews/tests lives in `tests/pos-sample.js`.
- Dashboard product form = exactly **Product name, Category, Brand, SKU, COGS** (owner's list, 2026-11-06; Brand added 2026-11-06). Keys `nama`, `kategori`, `brand`, `sku`, `cogs`; `sku`, `cogs`, `brand` are the last `Stok` columns. Category and brand are free text with suggestions (datalist) from values already used; no built-in category list. No Status field: the form's bottom button is Delete (no POS history) / "Hide from cashier" (sets `aktif` Inactive) / "Show in cashier again". Low-stock minimum defaults to 3 (`min` kept for old rows). Variant, selling price and online stock are no longer in the form (old values stay in the data; the list's −/+ still changes online stock). Duplicate SKUs are refused.
- POS stock history (Stok › Riwayat) leaves out **sales** (staff only see Masuk, Keluar, Transfer, Rusak, Opname); the dashboard history keeps sales. Manual moves can be edited (product + quantity; for opname the physical count, difference recomputed against stock without that move) by **anyone, no owner mode** (owner's decision 2026-11-06); the row is updated in place (same id) and its note gets "· diubah <date time>".
- Stock moves that take a location below zero need **no owner PIN** (owner's decision 2026-11-06); the form only warns "Stok … akan menjadi -N".
- Dashboard Products has **Import from spreadsheet**: paste cells copied from a sheet (tab/semicolon/comma separated; header row recognised in Indonesian or English: Produk/Nama, Category/Kategori, Brand/Merek, SKU/Kode, COGS/HPP/Modal; without a header the order is Product, Category, Brand, SKU, COGS), preview, then import. Rows without a name or with an existing SKU (case-insensitive) are skipped; amounts like "132.000" are read as 132000. Stock quantities are not imported (stock comes from POS moves). Never put the owner's real product list or COGS in the repo (it is public).
- Dashboard Operational > Stock has **Products | History**. History = POS stock moves with filters (period incl. custom dates, store/warehouse, type, category, brand, product/SKU search); only the list re-renders when a filter changes.
- Dashboard Production > **Supplier** (owner 2026-11-07), beside Purchasing and Manufacturing: one row per month from POS stock moves, per product (stock in with `dari` = `Supplier`) − (stock out with `ke` = `Supplier`), × product COGS, summed; transfers, Konveksi and void rows do not count. A month is paid the following month ("Pay in July 2026"). The month's recap sheet has **Copy** (plain digits, e.g. `1200000`) and **Mark as paid** (two taps to undo). Paid months live in the dashboard tab `Supplier` (`id` = `sup-<yyyy-mm>`, `bulan`, `total` at payment time, `paidOn`); paid months show a green checkmark. A tab the Sheet only just got (Code.gs updated late) arriving empty does not wipe rows made on this device (`newTab`, `S.cfg.tabs`).
- Dashboard Finance has **Transactions | Sales** (owner 2026-11-09). Sales = monthly recap: year pills, store filter, KPIs (revenue, pieces, change vs the same months of the previous year), month table (pieces, revenue, previous year, change; tap a month for store × product details), by store, top 10 products. Past months come from **Import sales history** (paste with header Date/Tanggal, Store/Toko, SKU, Sold/Qty, Total pendapatan/Revenue; dd/mm/yyyy or yyyy-mm; amounts like `23.425.000` or `12205000`; blank revenue = 0); rows of the same month + store + SKU are added up and stored in the dashboard tab `Penjualan` (`id` = `h-<yyyy-mm>-<store>-<sku>`, `bulan`, `toko`, `sku`, `qty`, `total`); importing again replaces those ids. Months/stores without imported rows use the POS (shift totals for revenue, sale moves for pieces). SKUs are shown by product name when the SKU exists in the product list. The owner's real sales data must never be committed (repo is public).
- Dashboard Finance also has **Report** and **Financial** (owner 2026-11-09, ported from the owner's own "Monthly Report" page, restyled to this dashboard) with **sample data only** (`FD` in `dashboard.html`, tagged "Sample data"; to be wired to real data later). Report: month filter (incl. year to date), KPI cards (revenue, pieces, cost) with trend lines and change vs the previous month / same period last year, revenue-vs-cost chart (bars + line on one Rp axis; tap a bar to pick the month, hover tooltip), category donut + table, product ranking with outflow, store ranking (tap = what it sold). Financial: all-time revenue/items, store and product ranking, yearly growth chart + table (revenue, cost, gross profit, items, growth; current year vs the same months), valuation (cash, material, product value) and stock per SKU at cost. Chart colours `--viz1` blue / `--viz2` orange (validated categorical pair, light + dark).
- Reminders have an optional **Link** (owner 2026-11-10), column `link` at the end of `Tugas`: either a dashboard page from the suggestion list (`PAGES`, e.g. "Production › Supplier", opens that tab/sub-tab) or a website (http/https only; "shopee.co.id" gets https://, opens in a new tab). Anything else is refused in the form. Reminder rows with a link show a round link button that opens it without opening the edit form.
- Store locations = dashboard `Store` tab. Types (owner 2026-11-08) are exactly **Physical store**, **Warehouse**, **Online store** (old `Marketplace` rows count as Online store). Warehouse = stock only, no sales, not offered as a tablet store. Physical store = a shop with a tablet. Online store = own sales on a tablet (receipts/shifts under its own name) but **no stock of its own**: column `sumber` ("Stock from", a physical store or warehouse) is where its sales take stock from (`SRC()` in the POS: sale moves, price-sheet stock, stock form location). Column `produk` = JSON list of product ids ticked for that store in the store form (checklist with search/All/None); all ticked is saved as `''` = all products, also ones added later. The POS cashier shows only the store's ticked products; the stock form/list shows the products ticked for the tablet's store (owner mode: the chosen location). History is keyed by store **name**: renaming a store splits its history.
- Dashboard Operational > Stock > Products is a **table** (owner 2026-11-08): product (name + category/brand/SKU), one column per warehouse/physical store, Total (red at or below the minimum); tapping a row opens the product. No −/+ buttons; online stock (`stokOnline`) is no longer counted (online stores use their source store's stock).
- "Mulai baru" (Owner > Data): `Code.gs` action `resetPos` clears all POS tabs and bumps `posEpoch`; every tablet that sees a new epoch wipes its local history (keeping an open shift). It waits for a running sync first and ignores answers to requests started before the reset.
- POS navigation is a menu under the top-left logo (no side rail / bottom bar: the owner found the rail laggy). Menu items act on touch-down; the following click is swallowed.
- POS payment (owner's decision 2026-11-07): no confirm step for a single payment. Tapping **Transfer** or **EDC** finishes the sale at once; tapping **Tunai** itself finishes the sale as exact cash (uang pas); below it at most **3** cash buttons with amounts **above** the total (no "Uang pas" button) finish the sale with change (shown on the success sheet). No method is pre-selected (2026-11-07). "Selesaikan transaksi" exists only for Split payment. Frequently used price chips: at most **3**.
- POS Kasir (2026-11-07): the category filter shows category **names** (first letter capitalised), no icons; product cards show only a **brand** pill (POS products carry `brand` from the dashboard); no category pill. Card colour per category (2026-11-07): Atasan blue, Gamis yellow, Bawahan red, Oneset purple, others white (solid colours, no `color-mix`).
- POS stock form (2026-11-07): a **Brand** picker beside **Produk** (default the brand matching "karmila", "Semua brand" possible) narrows the product list; layout like the price sheet (pickers + keypad left, quantity + stock info + big **Simpan** right); **Simpan saves at once**, there is no check screen; the below-zero warning shows inside the form. The sheet keeps its normal background (a tinted `color-mix` background was transparent on some tablets); only the Simpan button carries the colour (Masuk green, Keluar red).
- POS Struk (owner 2026-11-07): **anyone, no owner mode**, can open a receipt and choose **Ubah pembayaran** (one tap on Tunai/Transfer/EDC sets the whole total to that method, marks it "Diubah") or **Batalkan struk** (two taps, void). Items and prices are no longer editable on receipts. Cancelled receipts are struck through in the list with a "Dibatalkan" pill. After shift close both changes re-upload the receipt and the shift totals (void also adds stock correction moves).
- POS price sheet on tablets: keypad left, quantity + "Tambah ke keranjang" right (button must never drop below the fold).
- Receipt texts (Owner > Data > Teks struk): "Alamat / info" and "Pesan bawah" are multi-line text boxes; each typed line prints on its own line (long lines wrap), on screen and on paper.
- POS sounds (Web Audio, no files): tap on every button, chime on sale / shift close, low tone on errors; switch in Owner > Data.
- Printer: store tablet uses a **Kassen BT-P3200** (80 mm, Bluetooth + USB) with the cash drawer on the printer's drawer port. POS "Bluetooth langsung" prints ESC/POS via Web Serial over Bluetooth (SPP UUID 00001101-...) when `navigator.serial` exists, otherwise via Web Bluetooth (BLE, common printer services 18F0/18F1/E7810A71/49535343/FF00/FFE0/FFF0/AE30, **20-byte** pieces with write-with-response when the characteristic offers it, else 25 ms pauses; one job at a time). The owner's tablet had no Web Serial (2026-11-06); it connected over BLE and the drawer opened, but 180-byte pieces garbled long receipts, hence 20 bytes. Receipts end with `ESC d 5` + `GS V 1` (feed + partial cut). Auto-connect (2026-11-06, owner: staff must not have to reconnect): a header printer button (status dot + printer icon + the printer's own Bluetooth name from `S.cfg.prBleName`, e.g. "RPP02N" — the owner's printer advertises that name; green ready / amber not connected / spinner) shows in mode bt; on app open, after a dropped link and every 20 s while disconnected the POS reconnects silently to the saved printer (`S.cfg.prBle` id via `navigator.bluetooth.getDevices`, or `navigator.serial.getPorts`); where Chrome has no `getDevices`, one tap on the Printer button opens Chrome's picker filtered to the saved printer name (`S.cfg.prBleName`). Owner > Data > Sambungkan printer always opens the full picker. The printer settings line names the browser (Samsung Internet / in-app WebView have no Web Bluetooth). RawBT intent is the fallback and the system print dialog as the default mode. Drawer pulse `ESC p 0 25 250` on cash sales and cash in/out. Printing never blocks or undoes a sale. Not yet verified on the real printer.
- Dashboard design rules come from the `wismir-dashboard` skill: icon-only navigation, round green "+" add buttons, no colored backgrounds behind text labels, in-app two-tap delete (never `alert`/`confirm`/`prompt`), forms contain exactly the fields the owner asked for (if a new field is technically required, say so).
- New Sheet columns are appended **at the end** of a tab's header list in `Code.gs`.

## Workflow agreed with the owner

1. Make the change, run `bash tests/run_all.sh` (must print `EVERYTHING PASSED`), and for visual changes send previews: `node tests/make_preview.js <scratchpad-dir>`, then send the two files with display `render` (plus screenshots). Never commit preview files or logs.
2. Push to the session's `claude/...` branch and open a pull request into `main` (Indonesian title and description: summary, changes, testing, steps for the owner).
3. **Merging: always merge right away** once tests pass (owner's decision 2026-11-06), including `Code.gs` changes and cashier-flow changes. Follow the project skill **`wismir-ship`** (`.claude/skills/wismir-ship/SKILL.md`).
   - `Code.gs` changes must be safe to install late: new columns at the end, apps tolerate the old script (`keepMissing()` in the dashboard, fallbacks in the POS), and `CODE_VERSION` (Code.gs) = `NEED_CODE` (dashboard) bumped together so the dashboard shows "Update Code.gs" until the owner installs it.
   - After merging, tell the owner what changed (and the Code.gs steps if it changed). Revert quickly if they are unhappy.
   - The POS was still in trial on 2026-11-05. When it goes live, still merge right away, but point out in the message when a change touches checkout / sync / shifts.
4. If `Code.gs` changed, tell the owner: open `Code.gs` on GitHub → **Copy raw file** → paste in Apps Script → Ctrl+S → **Deploy → Manage deployments → Edit → New version → Deploy** (never "New deployment": that changes the URL on every device).
